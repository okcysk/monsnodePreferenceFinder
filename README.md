# Monsnode Preference Finder（ウェブ版）

4本の動画を同時に再生し、好きな順に 1〜4位 を付けるだけで、Pairwise GP 選好学習（GPPL）が一番好きな動画を探すウェブサイトです。インストールは不要で、学習と CLIP 埋め込みはすべてブラウザ内で行います。

**公開URL: https://okcysk.github.io/monsnodePreferenceFinder/**

Chrome 拡張版（`../monsnodeGPPL/`）と中身は同じです。違いは monsnode の読み方だけです。

| 処理 | ウェブ版での方法 |
|---|---|
| 一覧取得 | Cloudflare Worker の `/search` |
| 人気ランキング | Worker の `/search?ranking=1&period=…&page=`（period は 24h・3d・7d、1ページ目は page=0） |
| 動画 URL の解決 | Worker の `/resolve` |
| 再生 | twimg を直接再生し、失敗したら Worker の `/media` 経由で再生 |
| サムネ取得（CLIP 用） | `pbs.twimg.com` から直接取得（CORS 対応） |

Worker は Monsnode Multi Player と共用です（`../monsnodeWebPlayer/worker/`）。接続先は `config.js` の `GPPL_API_BASE` で指定します。

## 使い方
- 「プール取得」で候補を集める。初回は CLIP モデル（約90MB）をダウンロードし、以後はブラウザのキャッシュを使う
- 好きな順にクリック、または数字キー 1〜4 で順位を付ける。3つ選ぶと4位は自動で決まり、Enter で送信する
- 再生されない動画は「評価しない」ボタンか Q で外す
- W/A/S/D・Tab でフォーカスを移動する。Space・Z/X・C/V・F/G/H・M・↑↓ はフォーカス中のセルに効き、Shift を付けると4本すべてに効く。`?` で一覧を表示する
- 「マップ」（`viz.html`）で embedding の2次元マップを確認できる。サムネをクリックすると、その動画の4フレームと近傍を表示する（Esc・何もない所のクリック・「選択解除 ×」で解除）

学習データ（候補・埋め込み・比較履歴）は、このサイトの IndexedDB に保存されます。ブラウザごと・端末ごとに別々で、拡張版とも共有されません。

## 埋め込み方式（ヘッダのプルダウンで切り替え）
- **サムネのみ**（既定）：サムネ1枚を CLIP で埋め込む。速くて通信量も少ない
- **サムネ＋動画4フレーム**：動画を4区間に分け、各区間の中央のフレームを取り出して CLIP で埋め込み、サムネと合わせた5枚を平均する。中身をより反映するが時間がかかる（実測 1本あたり約2秒・4本並行、300本で約10分）
  - 非表示の `<video crossOrigin="anonymous">` でシークしてフレームを取り出す。twimg の MP4 は目次（moov）が先頭にあり、Range リクエストにも対応しているので、動画全体はダウンロードしない。それでも1本あたり数MBの通信が発生する
  - `video.twimg.com` は CORS を許可しているので、canvas から画素を読める。ただし Referer が付くと 403 になるため、ページで `no-referrer` を指定している
  - 目次（moov）の読み込みが8秒、全体が20秒を超える動画（数時間の動画など）は、この方式の候補から外す
  - 時間の大半は通信（シーク）待ちのため、4本を並行して処理する
- 埋め込みは方式ごとに別々に保存する。比較履歴は共通なので、方式を切り替えても学習結果を引き継いだまま、新しい特徴量で学習し直す
- マップ（`viz.html`）は、選んでいる方式の埋め込みを表示する

## CLIP の実行方式（ヘッダのプルダウン。変更するとページを再読み込み）
- **WASM**（既定）：量子化版（q8）で、モデルは約90MB。1枚あたり約0.25秒
- **WebGPU**：fp32 版で、モデルは約350MB。CLIP 単体では約2倍速い（実測で5枚 1.3秒→0.6秒）。フレームの5枚は1回のバッチでまとめて処理する。WebGPU が使えない環境では自動で WASM に戻す
- q8 と fp32 は、同じ画像でもベクトルが少し違う（コサイン類似度 0.89〜0.96）。混ぜると学習が崩れるので、embedding は実行方式ごとに別々に保存する。切り替えた直後は、その方式の埋め込みを作り直す（比較履歴は共通）
- WASM でバッチ処理をしないのは、q8 ではバッチにするとベクトルが変わり（同じ画像でコサイン類似度 0.978）、速度もほとんど変わらないため
- フレーム方式の処理全体は通信がボトルネックなので、WebGPU にしても全体の時間は大きくは縮まらない

## 人気の事前情報（monsnode の人気ランキング）
- 「プール取得」のときに、monsnode の人気ランキング（`?ranking=1&period=24h / 3d / 7d`、合計 約190本）も取得し、候補に加える。検索語がある場合は、ランキングの動画は加えず、集めた候補のうちランキングに入っている動画に印を付けるだけにする
- ランキングには再生数などの数値はなく、順位だけがわかる。期間が短いほど、順位が上ほど高いスコアにする（24h 1位 = 1.0 〜 7d 最下位 = 0.35）。過去に入ったランキングのうち、いちばん良いものを覚えておく
- ランキングに入っていない動画には、embedding から「人気の動画らしさ」を推定する。PCA 48次元でロジスティック回帰（ランキング入り vs それ以外）を学習し、交差検証の AUC が偶然（0.5）に近いほど、推定を平均に寄せる（AUC 0.75 以上で推定をそのまま使う）
- この人気（0〜1）を、GP の事前平均 m = α·(人気 − 平均) として学習に入れる（f = m + g）。比較がまだない動画も、人気がある方が μ が高くなり、UCB で先に出やすくなる。比較が増えると、あなたの回答（g）が優先される
- 強さ α はヘッダの「人気: 使わない／弱（0.3）／中（0.6、既定）／強（1.0）」で変える。「強」にすると、序盤はランキングの動画ばかりになりやすい
- 最初の4本は、事前平均の上位 40% の中から、ばらけるように選ぶ
- 合成ユーザーのテスト（好みと人気の相関 0.7）では、上位5%に届くまでのラウンド数が 4.4 → 2.6 に減った。人気と好みが無関係でも 4.3 で、悪化しない
- 実データの例：ランキング入り 65本、ランキング外への推定の AUC 0.60（手がかりは弱め）、事前平均の幅は −0.18〜+0.25（「中」の場合）
- ランキングの動画には、セルに「🔥7d 30位」のような印が付く。マップの「色」→「人気（ランキング＋推定）」で、人気と推定の当たり具合（AUC）を確認できる

## カーネル（ヘッダのプルダウン。好みの形の仮定）
GPPL のカーネルを切り替えられる。比較履歴は共通なので、切り替えるとすぐに同じ回答で学習し直す。
- **RBF**（既定）：`k = exp(−|x−x'|²/2ℓ²)`。好き度 μ は「比較した動画を中心とするガウスの山」の重ね合わせになり、好みの山がいくつあってもよい。離れた所では事前分布（0）に戻る
- **線形**：`k = x·x'/ℓ²`。f = w·x（好みの方向が1つ）。CLIP の embedding は長さ1に正規化してあるので、「好みの中心が1か所にある正規分布の山」とほぼ同じになる。推定するのは48次元の w だけなので、少ない回答で安定する
- **2次**：`k = (x·x'/ℓ² + 1)²/4`。2次関数の f。方向ごとに広がりが違う、楕円の山が1つ
- ℓ は RBF なら距離の中央値、線形・2次なら |x| の二乗平均の平方根から始め、比較が20件を超えたら周辺尤度で選び直す
- 切り替えたときにステータス欄に出る「周辺尤度」は、同じ回答データをそのカーネルでどれだけよく説明できるかの目安（大きいほど良い）。カーネル同士で比べられる
- 合成ユーザーのテスト（10シード・20ラウンド、上位5%に届くまでの平均ラウンド数）：好みの方向が1つのユーザーで RBF 3.8／線形 3.4／2次 4.1、好みの山が3つのユーザーで RBF 6.6／線形 6.3／2次 7.5。差は小さく、山3つでも線形は悪くなかった（32次元の単位球面では山が広く、上位は一番大きな山の方向に集まるため）
- 1回ごとのシミュレーション結果は、ページを読み込み直すと少し変わることがある（ブラウザの計算の細かい丸め誤差が20ラウンドの間に増幅されるため）。比べるときは複数シードの平均を見る

## タグとテキスト検索（マップ・CLIP ゼロショット）
- マップの「色」で「タグ: アニメ」などを選ぶと、そのタグらしさ（0〜100%）で枠を色分けし、50%未満を薄く表示する。サムネを選ぶと、パネルに各タグの%が出る
- 判定方法：各タグに「当てはまる説明」と「対比する説明」の英文を用意し、動画の embedding がどちらに近いかを CLIP のテキスト側の埋め込みで比べる（`P = sigmoid(100·(x·p − x·n))`）。学習は不要で、既にある embedding をそのまま使う
- 既定のタグは アニメ／露出（屋外）／海外／浴室／ベッド／車内／水着／コスプレ／ランジェリー／金髪／自撮り／オーラル／グラマー／スレンダー／おもちゃ／拘束／アップ／芸術的／楽しそう の19個。すでにタグを保存しているブラウザには、そのあと増えた既定タグを一度だけ末尾に追加し、既定から外したタグ（v0.9.2 のおしっこ）は、変更していなければ一度だけ取り除く（自分で作ったタグや変更はそのまま残す。消したタグは以後戻さない）。対比する説明には近い別の状態（裸・下着・水着など）も入れている。たとえば「水着 vs 普段着」だけだと、薄着のサムネの多くが水着と判定されてしまうため（実データ165本で 141本 → 19本）。「タグ編集」で追加・変更・削除でき、`|` で区切ると複数の言い回しを平均する。タグはブラウザに保存される
- 「タグ名」にチェックを入れると、各タグの名前（と「英語で探す」の文章）を、マップ上の1か所にだけ表示する。場所は、そのタグらしさが50%以上の動画のうち、512次元の embedding 空間で同じタグの動画がいちばん密集している中心の動画（`argmax_i w_i·Σ_j w_j·exp((cos_ij − 1)/0.05)`、w = タグらしさの50%を超えた分）。ぽつんと離れた1本や、まとまりの間の何もない所には付かない。ラベルが重なるときは上に積む
- マップ上のタグ名（またはサムネを選んだときのパネルのタグ）をクリックすると、そのタグらしさが高い順に動画の一覧（50%以上の動画。少なくとも12本、多くても60本）をパネルに出し、マップでもその動画以外を薄くする。一覧の動画をクリックすると詳細を表示し、「← ○○ の一覧」で一覧に戻る。「英語で探す」の文章のラベルも同じように一覧を出せる。同じタグをもう一度クリックするか、「選択解除 ×」・Esc でタグの選択を解除し、色分けも選ぶ前（好き度 μ など）に戻す
- パネルの「▶ この動画と近傍を4画面で再生」「▶ 上位を4画面で再生」で、選んだ動画と近傍（最大13本）、またはタグ・検索の上位（最大60本）を2×2で上から順に再生する。終わった動画（読み込めない動画も）のセルは、次の未再生の動画に自動で入れ替わる。最後まで行くとその動画を繰り返す
  - ショートカットはほかの 4movPlayer と同じ：W/A/S/D・Tab でフォーカス（緑の枠）、Space 再生/停止、Z/X 5秒、C/V 30秒、F 1.0x、G/H 2.5x/10x 切替、M ミュート、↑↓ 音量。Shift を付けると4本すべてに効く
  - N（または Enter）でフォーカス中のセルを次の動画へ、←/→ で前/次の4本。セルをクリックするとその動画の音だけを出す（もう一度で消音）。Esc で閉じる
- 「英語で探す」に文章を入れて Enter を押すと、その文章に近い動画の上位10%を強調する（例: `beach | seaside`）
- テキスト側のモデル（q8、約65MB）は、マップで初めて使うときにダウンロードする。テキストは1文ずつ処理する（q8 ではまとめて処理すると、タグを増減しただけで他のタグの判定が変わってしまうため）
- 見た目からの推測なので、外れることもある。特に「海外」は人物の見た目からの推測にすぎない

## ローカルで動かす
ES モジュールと Web Worker を使うので、`file://` では動きません。HTTP で配信してください。

```
python -m http.server 8771 --directory monsnodeGPPLWeb
```

`.claude/launch.json` の `monsnode-gppl-web` でも起動できます。

## 公開
静的ファイルだけなので、GitHub Pages などにそのまま置けます。`vendor/ort-wasm-simd-threaded.jsep.wasm`（21MB）は GitHub の1ファイル100MB制限に収まります。
